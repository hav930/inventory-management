System Architecture

Data Flow

Example: user selects Q2-2025 in the dashboard time filter

  1. UI event User picks Q2-2025 in FilterBar.vue; the shared useFilters() composable updates its selectedPeriod ref.
  2. Reactive trigger Dashboard.vue watches the filter state and calls api.getDashboardSummary({ month: 'Q2-2025', ... }).
  3. HTTP request client/src/api.js builds query params and issues GET /api/dashboard/summary?month=Q2-2025.
  4. Route handler FastAPI routes the request to get_dashboard_summary() in server/main.py.
  5. Filter filter_by_month() expands Q2-2025 to ['2025-04','2025-05','2025-06'] and slices the in-memory orders list.
  6. Aggregate Handler computes total_inventory_value, low_stock_items, pending_orders, total_backlog_items, total_orders_value.
  7. Response JSON dict is serialized and returned; browser receives the payload.
  8. Render Dashboard.vue assigns the result to a ref; computed properties recalculate and SVG charts re-render.

Design Notes

Single source of filter state

The useFilters() composable is a singleton — refs live at module scope, so every view and the filter bar share one source of truth.

No database

JSON fixtures load once at server import time into plain lists. Mutations don't persist; restart restores the original state.

Quarters as a server concern

Quarter strings (Q1-2025 … Q4-2025) are expanded server-side into month lists, so clients send one tidy param.

Computed-first rendering

Raw API responses live in refs; everything derived (totals, formatted currency, chart series) is a computed for cached re-evaluation.

Permissive CORS for dev

allow_origins=["*"] is set explicitly as a dev convenience. The backend's own CLAUDE.md flags this as not production-safe.

Endpoints referenced but not implemented

api.js calls /api/tasks and /api/purchase-orders routes that aren't defined in main.py — modal features that depend on them will fail until those handlers are added.
